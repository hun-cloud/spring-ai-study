# AI 애플리케이션의 핵심 개념

## AI 모델

### 대규모 언어모델 Large Language Model (LLM)
- AI모델은 인간의 인지 기능을 모방해서 정보를 처리하고 생성하도록 설계된 알고리즘.
- 대규모 데이터셋에서 패턴과 인사이트를 학습하여 예측, 텍스트 생성, 이미지 생성 등 가능
- 최신 모델들은 이미지, 오디오, 비디오 등 다양한 형태의 데이터를 동시에 이해하고 생성할 수 있는 멀티모달 기능을 갖추고 있음

### 이미지 생성 모델
- 텍스트나 기존 이미지를 바탕으로 시각적 컨텐츠를 창작하는 모델

### 음성 모델
- 소리 데이터와 텍스트 간의 변환을 담당.
- 오디오를 입력받아 텍스트로 변환하거나 반대로 텍스트를 입력받아 자연스러운 오디오로 변환

### 임베딩 모델
- 데이터의 의미를 기계가 이해할 수 있는 숫자로 나열하여 벡터로 변환하는 모델.
- 텍스트, 이미지 등 다양한 데이터를 입력받아 벡터로 출력
- 벡터값 기반으로 의미의 유사성을 계산할 수 있으므로 검색 시스템이나 추천 알고리즘의 핵심 기술로 사용됨

## 토큰
- AI 모델은 사용자가 입력한 문장을 통쨰로 이해하지 않음.
- 대신 텍스트를 토큰이라는 더 작은 단위로 쪼개서 처리

## 프롬프트
- AI 모델이 작업을 수행하도록 지시하는 명령어 또는 입력 텍스트
  - 시스템 역할 : 모델이 전반적으로 어떻게 행동해야 하는지 페르소나와 맥락 설정
  - 사용자 역할 : 실제 사용자가 입력하는 구체적인 질문이나 명령
  - 어시스턴트 역할 : 모델이 이전에 응답했던 내용으로, 대화의 흐름을 이어나가기 위해 사용.

> 스프링 AI에서는 SystemMessage, UserMessage, AssistantMessage와 같은 클래스를 제공하여 역할별 메시지를 자바 코드로 자연스럽게
> 다룰 수 있게 지원한다.

- 프롬프트 엔지니어링(Prompt engineering) : 질문과 지시사항을 정교하게 다듬는 단계
- 컨텍스트 엔지니어링(Context engineering) : 모델에게 사내 문서나 대화 이력 등 필요한 배경지식을 묶어서 제공하는 단계
- 하네스 엔지니어링(harness engineering) : AI가 여러 외부 도구를 호출하여 자율적으로 동작하도록 시스템 전체의 틀과 통제권을 설계하는 단계
- 스프링 AI는 이 세가지 단계를 자바 환경에서 일관되게 다룰 수 있도록 다양한 기능(PromptTemplate, VectorStore, 도구 호출 등)을 지원

## 벡터와 벡터 공간

### 벡터
- 벡터는 데이터의 의미를 숫자의 나열(배열)로 표현한 것. 예: `[0.12, -0.87, 0.45, ...]`
- 임베딩 모델이 텍스트, 이미지 등을 입력받아 출력하는 결과물이 바로 벡터이며, 이를 임베딩(embedding)이라고 부름
- 벡터를 구성하는 숫자의 개수를 차원(dimension)이라고 하며, 모델마다 고정된 차원을 가짐 (예: OpenAI text-embedding-3-small은 1536차원)
- 핵심은 **의미가 비슷한 데이터는 비슷한 숫자 패턴의 벡터로 변환된다**는 것
  - "강아지"와 "반려견"은 서로 가까운 벡터가 되고, "강아지"와 "자동차"는 먼 벡터가 됨
- 단어의 표면적인 철자가 아니라 의미를 기준으로 비교할 수 있게 해주는 것이 벡터의 가장 큰 가치

### 벡터 공간
- 벡터들이 존재하는 다차원 공간. 각 벡터는 이 공간 위의 한 점(좌표)으로 볼 수 있음
- 벡터 공간에서는 **두 점 사이의 거리(또는 각도)가 의미의 유사도**를 나타냄
  - 가까이 있는 벡터 = 의미가 유사한 데이터
  - 멀리 있는 벡터 = 의미가 다른 데이터
- 유사도를 계산하는 대표적인 방법
  - 코사인 유사도(Cosine Similarity) : 두 벡터 사이의 각도를 측정. 방향이 같을수록 1에 가까움. 텍스트 검색에서 가장 널리 사용됨
  - 유클리드 거리(Euclidean Distance) : 두 점 사이의 직선 거리. 짧을수록 유사함
  - 내적(Dot Product) : 두 벡터의 곱의 합. 정규화된 벡터라면 코사인 유사도와 동일한 결과
- 이 원리를 활용한 것이 **의미 기반 검색(Semantic Search)**
  1. 문서들을 미리 벡터로 변환하여 저장
  2. 사용자의 질문도 벡터로 변환
  3. 질문 벡터와 가장 가까운 문서 벡터들을 찾아 반환
- 이렇게 벡터를 저장하고 유사도 검색을 수행하는 데 특화된 데이터베이스가 벡터 스토어(Vector Store)이며, RAG(검색 증강 생성)의 핵심 인프라가 됨

#### 벡터 공간 예시 (2차원으로 단순화)

실제 벡터는 수백~수천 차원이지만, 이해를 돕기 위해 2차원 평면으로 표현하면 아래와 같다.
의미가 비슷한 단어들끼리 가까운 위치에 모여 군집을 이룬다.

```
  ▲
  │        · 강아지                      · 자동차
  │      · 반려견                          · 버스
  │        · 고양이                      · 트럭
  │
  │                                              [동물 군집]과 [탈것 군집]은
  │           ★ 질문: "귀여운 애완동물"           서로 멀리 떨어져 있음
  │
  │      · 햄스터
  │
  └──────────────────────────────────────────────▶

  ★ 질문 벡터와 가장 가까운 점들(강아지, 반려견, 고양이, 햄스터)이
    유사도 검색의 결과로 반환된다.
```

코사인 유사도는 원점에서 각 벡터를 향한 화살표 사이의 "각도"를 비교하는 방식이다.

```
  ▲
  │      강아지
  │      ↗
  │    ↗   θ₁ (작은 각도 → 유사도 높음)
  │  ↗ ─────▶ 반려견
  │ ↗
  │↗  θ₂ (큰 각도 → 유사도 낮음)
  └──────↘─────────────────▶
          ↘
            ↘ 자동차
```

> 스프링 AI에서는 EmbeddingModel 인터페이스로 텍스트를 벡터로 변환하고, VectorStore 인터페이스로 벡터의 저장과
> 유사도 검색(similaritySearch)을 추상화한다. 덕분에 PGVector, Redis, Chroma 등 다양한 벡터 DB를 동일한 코드로 다룰 수 있다.



### AI 모델의 데이터와 API 확장
- 학습이 멈춘 AI 모델은 어떻게 최신 뉴스나 회사의 비공개 내부 데이터를 어떻게 알려줄 수 있을까?

#### 파인튜닝
- 파인튜닝은 전통적인 머신러닝 기술로 모델의 가중치를 조정.
- 모델 자체를 바꾸는 방식이어서 전문성, 학습 비용, 시간이 많이 든다.
- 실시간 데이터를 반영해야 한다면 적합하지 않은 방식

### RAG
- RAG는 AI 모델이 미리 학습한 데이터에만 의존하지 않고, 외부에서 필요한 정보를 찾아 그 내용을 바탕으로 답변을 생성.
- AI 모델에게 질문을 보낼 때 관련 데이터를 프롬프트 공간 안에 가득 채워 넣는 프롬프트 스터핑 방식으로 구현할 수 있음.

### 도구 호출
- AI 모델이 외부 시스템의 API를 호출할 수 있도록 권한을 주는 기술.
- 이를 통해 AI는 실시간 주가 정보 조회나 이메일 발송과 같은 행동을 수행할 수 있다.
- AI 모델이 외부 도구를 활용해 좀 더 능동적으로 작업을 수행할 수 있도록 확장할 수 있다.
