# 스프링 AI 이해하기

### AI 모델을 제공하는 업체별로 API를 직접 호출하고 관리하는 방식의 문제
1. 높은 복잡도 : 개발자는 HTTP 클라이언트를 실행하고, API 명세를 일일이 확인하며, 요청과 응답을 수동으로 분해하고 해석해야 한다.
2. 공급자 종속성 : 오픈 AI의 모델을 사용하기 위해 코드를 작성했다가, 나중에 구글이나 엔트로픽 등 다른 업체의 모델을 사용하려면 AI 모델과 통신하는 코드를 거의 전부 다시 작성해야 한다.
3. 컨텍스트 관리의 어려움 : AI 모델은 기본적으로 회사 내부 데이터나 특정 도메인 지식을 알지 못한다. 단순히 질문만 던져서는 원하는 답을 얻기 어렵다. 제대로된 답변을 이끌어 내려면 컨택스트 관리 로직을 일일이 구현해야하는 번거로움이 따른다. 

## 스프링과 AI를 쉽게 연결하는 방법
- 스프링 AI는 개발자가 스프링 부트에 기반한 애플리케이션에 AI 기능을 쉽게 통합할 수 있또록 돕는 프레임워크.
- AI 모델과의 복잡한 통신 과정을 단순화하고 효율적으로 관리할 수 있도록 설계.
- 애플리케이션과 다양한 AI 모델 공급자 사이에 위치하는 추상화 계층 역할을 함.
- 내부적으로 API를 호출하는 과정을 관리해 여러 AI 모델 공급자를 코드 변경 없이 플러그인처럼 교체할 수 있게 함.

### 스프링 AI의 핵심 철학
기업이 보유한 엔터프라이즈 데이트와 API를 AI 모델과 순조롭게 연결하므로 자바 개발자들은 익숙한 스프링 환경에서
AI 애플리케이션을 손쉽게 구축할 수 있다.

## 스프링 AI의 핵심 기능
- AI 모델과 소통할 수 있는 공통 인터페이스 제공, 설정만 변경해서 AI 모델을 쉽게 교체할 수 있음.
- ChatModel, ChatCLient 등 다양한 인터페이스를 스프링 빈으로 제공하여 개발자가 이를 일반적인 서비스처럼 @Autowired나 생성자를 통해 주입받아 사용할 수 있다.
- 프롬프트를 외부 파일로 저장해 관리할 수 있음, 
- 프롬프트 엠플릿을 만들어 두고 동적으로 변경할 값을 파라미터로 전달 가능.
- 프롬프트 내부에 '시스템', '사용자', '어시스턴트' 같은 역할 정의해 AI 모델이 특정 역할을 수행하도록 유도.
- 임베딩 및 검색 증강 생성 지원 기능
  - 일반적인 AI 모델은 학습 데이터에 없는 최신 정보나 기업 내부 문서는 알지 못함.
  - 임베딩과 검색 증강 생성(Retrieval-Augmented Generation, RAG) 기능을 사용할 수 있다.
  - 임베딩은 텍스트를 AI가 비교하고 검색할 수 있는 숫자 형태로 변환하는 기술.
  - RAG는 AI 모델이 답변을 생성하기 전에 외부 문서나 지식 기반을 먼저 검색해 그 내용을 참고하도록 하는 방식
  - 스프링 AI는 이 기능을 쉽게 사용할 수 있도록 지원.
- 대화형 AI를 위한 메모리 관리와 스트리밍 응답 가능
  - 기본적으로 LLM은 상태가 없는 모델이므로 방금 전에 나눈 대화를 기억하지 못함. -> 챗봇을 만들 때 문제
  - 스프링 AI는 채팅 기록과 메모리 기능을 제공해 이 문제를 해결한다.
  - 설정에서 최근 20개의 대화를 기억하도록 지정 가능, 이 대화 기록을 임시 메모리에 저장하거나 DB에 영구 저장하여 과거 맥락을 그대로 유지한 채 대화를 이어나갈 수 있게 만들 수 있음
  - 스트리밍 응답도 쉽게 구현할 수 있도록 지원.
