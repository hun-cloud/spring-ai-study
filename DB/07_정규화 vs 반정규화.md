# 정규화 VS 반정규화
"정규화의 목적은 무엇이며, 반대로 반정규화는 언제, 왜 사용하나요?"

> "정규화는 그냥 테이블 쪼개는 것 아닌가?"
>
> "반정규화는 귀찮으니까 정규화를 안하는거죠?"
> 
> 목적과 과정이 빠졌다.
> 
> "쪼개는 것은 수단이고, 목적은 데이터 무결성이다. 반정규화는 정규화 후에 수행하는 전략적 선택이다."

## 이상현상 (Anomaly) 발생

### 갱신 이상 (Update)
홍길동 주소를 2개만 고치고 1개를 빼먹으면?
-> 데이터 불일치

### 삽입 이상 (Insert)
주문 안 한 신규 회원은?
-> 주문 정보 없이 등록 불가

### 삭제 이상 (Delete)
마지막 주문을 취소하면?
-> 회원 정보까지 같이 삭제됨

## 1. 정규화 (Normalization)

### 핵심 : "중복 제거를 위한 구조화"
데이터를 주제별로 쪼개서(Split) 중복을 없애고 이상 현상(Anomaly) 방지

### 정규화의 대가 : 조인(Join)의 공포
쪼개놓으니 관리는 편한데, 한 번 조회할 때마다 테이블 3~4개를 합쳐야(Join) 하네? -> 읽기 성능 저하 발생

## 반정규화 (Denormalization)
### 핵심 : "읽기 성능 최적화"
성능을 위해 일부러 중복을 허용하고 테이블을 합치커나 컬럼을 추가.
-> 빠르게 찾지만 정리는 안됨

## 실무 적용 : 주문 이력 (Business)
"반정규화는 성능뿐만 아니라 비즈니스 로직 때문이기도 하다."
-> 이력 보존을 위해 데이터를 중복 저장(스냅샷) 해야 함.

> "정규화 없이 반정규화 하지 마라"
> 반정규화는 정규화된 모델을 바탕으로, 성능 문제가 생겼을 때 전략적으로 무너뜨리는 것.
> (처음부터 중복되게 설계하는 건 그냥 '잘못된 설계' 이다.)

## 한 눈에 비교 (Summary)
| 구분 | 정규화 | 반정규화 |
|-|-|-|
|목적 | 데이터 무결성, 중복 최소화 | 읽기 성능 향상, 조회 편의성 |
|장점 | 이상 현상 방지, 저장 공간 절약 | 조인 감소, 빠른 조회 속도 |
|단점 | 조인 증가로 인한 읽기 성능 저하 가능성 | 데이터 중복, 불일치 위험, 공간 낭비 |
|순서 | 기본 | 필요시 선택 |


### Q1. 제 1,2,3 정규화의 핵심 키워드는?
- 1NF : 원자값
- 2NF : 부분 함수 종속 제거 (PK 전체 의존)
- 3NF : 이행 함수 종속 제거 (A -> B -> C X)

### Q2. 반정규화 대신 쓸 수 있는 다른 성능 향상 방법은?
- 인덱스 튜닝
- 뷰 사용
- 캐시 도입
- 반정규화는 최후의 수단

### NoSQL은 정규화 안하나요?
- NOSQL은 읽기 성능을 위해 설계 단계부터 데이터를 중복 저장(Embedding) 하는 반정규화 방식을 지향
